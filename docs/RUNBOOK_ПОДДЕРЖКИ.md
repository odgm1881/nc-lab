# Runbook поддержки НК-ЛАБ

## Первичная диагностика

1. Записать время, пользователя, действие и `x-correlation-id` из ответа.
2. Проверить `/api/health/live` и `/api/health/ready`.
3. Найти JSON-лог по correlation ID; содержимое карточек и токены в заявку не копировать.
4. Проверить метрики запросов и рост ответов `5xx`/`429`.
5. Для импорта скачать построчный отчёт ошибок; исходный файл не пересылать без согласия.

## Критичность

- **P0:** потеря/утечка данных, доступ к другому клиенту, весь сервис недоступен.
- **P1:** не работает импорт, валидация или экспорт для всех пользователей.
- **P2:** частичная ошибка с обходным решением.
- **P3:** косметика или пожелание.

При P0 остановить затронутую операцию, сохранить логи и уведомить владельца сервиса.
Не удалять данные и не откатывать БД без проверенной резервной копии.

## Восстановление

Backup и restore выполняются только по `docs/РЕЛИЗ_И_ОТКАТ.md`. Сначала восстановить
копию в отдельную БД с суффиксом `_restore_test`, проверить таблицы и ревизию Alembic,
и лишь затем принимать решение о production-восстановлении.

## Контроль интеграции НК

1. Открыть раздел «Интеграция НК» и проверить количество ошибок, ожидающих НК
   операций и карточек с изменившимися данными.
2. Повторяемые ошибки имеют `next_retry_at`. Планировщик окружения должен вызывать
   `POST /api/integration/nk/exchanges-queue/retry-due` от имени технического
   редактора не реже одного раза в пять минут.
3. Ошибки маппинга не повторять автоматически: сначала исправить подтверждённые
   `cat_id`/`attr_id`, затем выполнить ручной повтор.
4. После изменения карточки использовать «Сверить». Статус `stale_payload` означает,
   что ранее подготовленный или отправленный пакет больше не соответствует карточке.

## Контроль доступа

- Администратор организации управляет пользователями и ролями в разделе «Команда».
- Редактор может импортировать и изменять карточки, пилоты и операции обмена.
- Наблюдатель имеет только чтение и экспорт; сервер отклоняет изменяющие запросы с 403.
- Нельзя понизить роль последнего администратора организации.
- Изменение роли действует сразу, включая уже выданные токены, потому что роль
  проверяется по базе данных на каждом запросе.
