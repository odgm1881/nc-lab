# Runbook поддержки НК-ЛАБ

## Первичная диагностика

1. Записать время, пользователя, действие и `x-correlation-id` из ответа.
2. Проверить `/api/health/live` и `/api/health/ready`.
3. Найти JSON-лог по correlation ID; содержимое карточек и токены в заявку не копировать.
4. Проверить метрики запросов и рост ответов `5xx`/`429`.
5. Для импорта скачать построчный отчёт ошибок; исходный файл не пересылать без согласия.

## Критичность

- **P0:** потеря/утечка данных, доступ к другому клиенту, весь сервис недоступен.
- **P1:** не работает импорт, валидация или экспорт для всех пользователей.
- **P2:** частичная ошибка с обходным решением.
- **P3:** косметика или пожелание.

При P0 остановить затронутую операцию, сохранить логи и уведомить владельца сервиса.
Не удалять данные и не откатывать БД без проверенной резервной копии.

## Восстановление

Backup и restore выполняются только по `docs/РЕЛИЗ_И_ОТКАТ.md`. Сначала восстановить
копию в отдельную БД с суффиксом `_restore_test`, проверить таблицы и ревизию Alembic,
и лишь затем принимать решение о production-восстановлении.
