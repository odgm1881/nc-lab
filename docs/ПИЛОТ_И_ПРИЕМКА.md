# Пилот и приёмка НК-ЛАБ

## Перед стартом

- Назначить владельца пилота со стороны клиента и НК-ЛАБ.
- Зафиксировать категорию, 50–100 исходных карточек и профиль выгрузки 1С/ERP.
- Удалить из тестового файла лишние персональные и коммерчески чувствительные данные.
- Проверить staging: `/api/health/ready`, закрытый `/api/metrics`, S3 и свежий backup.
- Выполнить тест восстановления по `docs/РЕЛИЗ_И_ОТКАТ.md`.

## Сценарий пользователя

1. Загрузить файл, проверить предпросмотр и сохранить профиль колонок.
2. Скачать протокол строк, исправить технически неразобранные строки.
3. Открыть каталог, выполнить массовую проверку и безопасные массовые исправления.
4. Создать запуск в разделе **Пилоты**, указать период, ответственного и участников,
   добавить карточки выборки и нажать **Запустить** для фиксации состава.
5. Разобрать ошибки GTIN, атрибутов и РД; спорные карточки передать оператору.
6. Оператор фиксирует причину эскалации, берёт задачу в работу и завершает её только
   с записанным результатом решения; при заданном сроке кабинет показывает просрочку.
7. Отметить валидные карточки готовыми и скачать файловый пакет НК.
8. На странице пилота проверить KPI только зафиксированной выборки и скачать CSV-отчёт.

## Что измерять

- число и долю успешно импортированных строк;
- время от загрузки до готовой карточки;
- долю карточек, прошедших проверку с первого раза;
- число ручных исправлений и минуты работы оператора;
- найденные дефекты с критичностью и шагами воспроизведения;
- число возвратов карточек после проверки клиента.

Кабинет автоматически считает успешность импорта, долю импортированных карточек,
валидных с первого прохода, медиану времени до готовности, долю решённых задач,
медиану работы оператора, просрочки и наиболее частые коды ошибок. Первая выборка
считается набранной после 50 карточек. CSV — это технический срез; исходный baseline
ручного процесса клиента и стоимость часа оператора всё равно фиксируются владельцем пилота.

Локальная техническая проверка граничного объёма этапа 1:

```bash
cd backend
uv run python scripts/pilot_benchmark.py --rows 500
```

Скрипт использует временную SQLite-базу, не меняет рабочие данные и завершится с
ошибкой, если создано не 500 карточек или хотя бы одна карточка не прошла правила.
