## Что за проект

НК-ЛАБ — платформа для подготовки и валидации карточек товаров для Национального
каталога и маркировки (Честный ЗНАК). Клиенты: импортёры одежды и селлеры
маркетплейсов. Главная ценность — валидация карточек, вариаций, GTIN и РД **до**
заказа кодов. Мы не «печатаем этикетки», мы устраняем ошибки на этапе описания.

Сейчас идёт этап 1 (MVP): 3 пилота, 300–500 карточек.

## Стек (кратко)

- Бэкенд: Python 3.13, FastAPI, SQLAlchemy 2.0, Alembic, PostgreSQL (JSONB), Pydantic v2.
- Пакеты/линт/тесты: uv, ruff, pytest.
- Фронтенд: Vite + React 19 + TypeScript + Ant Design 6 + React Router + axios.
- Инфра: Docker Compose, российское облако (Yandex/VK/Selectel), S3, JWT.

## Архитектура (кратко)

Модульный монолит. Внутри — модули по фичам в `app/modules/`, у каждого свои слои.
Правило: **доменная логика не зависит от FastAPI и SQLAlchemy.**
- `router.py` — только HTTP.
- `service.py` — сценарии и транзакции.
- `domain.py` / `domain/` — чистый Python, тестируется без базы и HTTP.
- `models.py` / `repository.py` — SQLAlchemy и доступ к данным.

Проверка при написании кода: если функцию можно протестировать без базы и без
HTTP — она в доменном слое.

## Обязательные правила кодовой базы

- Организация по фиче, не по типу файла. Новый функционал — новый модуль в `app/modules/`.
- Схемы хранения (SQLAlchemy) и схемы API (Pydantic) держим раздельно. SQLModel не используем.
- Гибкие атрибуты категорий — в JSONB. Поля для поиска/уникальности/джойнов — колонками.
- Любое изменение схемы БД — через миграцию Alembic. Прямых правок схемы нет.
- Статусы задач и импорта храним полем `status` в Postgres. Брокеров и очередей на этапе 1 нет.
- Секреты только через переменные окружения и `pydantic-settings`. В коде и коммитах секретов нет.
- Новый код сопровождается тестами: доменную логику — юнит-тестами, API — через httpx.

## Правило легпрома (не нарушать)

1 GTIN = 1 карточка. Цвет и размер — отдельные вариации, не смешиваются в одной записи.
Ошибка в GTIN необратима, поэтому GTIN проверяется до заказа кодов.

## Границы этапа 1 (не делать без запроса)

Микросервисы, Kafka/RabbitMQ, Celery/Redis-очереди, Kubernetes, GraphQL, ML в проде,
мультитенантность на уровне схем БД. Всё это отложено. Если кажется, что нужно —
сначала спроси.

## Команды

```bash
# бэкенд (запускать из папки backend/)
uv sync                     # установить зависимости
uv run uvicorn app.main:app --reload   # запустить API
uv run pytest               # тесты
uv run ruff check .         # линт
uv run ruff format .        # форматирование
uv run alembic revision --autogenerate -m "msg"   # новая миграция
uv run alembic upgrade head # применить миграции
uv run python -m app.seed   # заполнить демо-данными

# фронтенд (из папки frontend/)
npm run dev                 # дев-сервер
npm run build               # сборка
npm run lint

# инфраструктура
docker compose up -d
```
