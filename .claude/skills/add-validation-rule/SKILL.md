# Добавление правила валидации

Ядро правил — самый ценный модуль и главный барьер для конкурентов. Правила меняются
часто, потому что меняются требования НК. Держим их простыми и изолированными.

Модуль: `app/modules/validation/`.

## Принцип

Каждое правило — **чистая функция**: получает карточку, возвращает список ошибок и
предупреждений. Никакого движка правил или DSL.

```python
# app/modules/validation/domain/rules.py
from app.modules.validation.domain.result import Issue, Severity

def rule_gtin_unique_per_card(card, context) -> list[Issue]:
    """1 GTIN = 1 карточка. Цвет и размер — отдельные вариации."""
    issues: list[Issue] = []
    if <нарушение>:
        issues.append(Issue(
            code="GTIN_NOT_UNIQUE",
            severity=Severity.ERROR,
            message="GTIN уже привязан к другой карточке.",
        ))
    return issues
```

## Порядок добавления правила

1. Напиши функцию правила в `domain/rules.py`. Функция чистая: без базы и HTTP.
2. Зарегистрируй её в реестре `domain/registry.py`.
3. Добавь юнит-тест: минимум один кейс-нарушение и один валидный кейс.
4. Если правило доменное (GTIN, вариации, РД) — сверься с навыком `nk-domain`.

## Требования к правилу

- **Изолированность.** Правило не знает про FastAPI и SQLAlchemy.
- **Понятный код ошибки.** Стабильный машиночитаемый `code` (например, `RD_MISSING`)
  плюс человекочитаемое сообщение.
- **Severity.** Различай `ERROR` (блокирует ввод в оборот) и `WARNING`.
- **Одно правило — одна проверка.**

## Почему так

При изменении требований НК ты правишь или добавляешь одну функцию и её тест, а не
переписываешь приложение.
