# Новый модуль бэкенда

Создавай модули по фиче в `app/modules/<имя>/`. Не по типу файла. Соблюдай слои и
направление зависимостей: HTTP → сервис → домен → инфраструктура.

## Структура модуля

```
app/modules/<имя>/
├── __init__.py
├── router.py       # API-слой: роутеры FastAPI. Только HTTP, ноль бизнес-логики.
├── schemas.py      # Pydantic-схемы запросов и ответов.
├── service.py      # Сценарии, оркестрация, транзакции.
├── models.py       # SQLAlchemy-модели (если модулю нужна своя таблица).
├── repository.py   # Доступ к данным (если есть модели).
└── domain.py       # Чистая бизнес-логика. Без FastAPI и SQLAlchemy.
                    # Для сложной логики — папка domain/ вместо файла.
```

Модулю не всегда нужны все файлы. Если модуль чисто вычислительный (например,
`variations`), у него может быть только `domain.py`, `service.py`, `schemas.py`.

## Правила

1. **Доменный слой не импортирует FastAPI и SQLAlchemy.**
2. **Схемы раздельно.** `schemas.py` (Pydantic) и `models.py` (SQLAlchemy) — разные
   классы. SQLModel не используем.
3. **Модули не лезут в чужие таблицы.** Обращение к другому модулю — через его сервис.
4. **Роутер подключается в `app/main.py`** через `include_router`.

## Порядок работы

1. Создай папку модуля и файлы по структуре выше.
2. Опиши доменную логику и сущности в `domain.py` — начни с неё, а не с HTTP.
3. Опиши Pydantic-схемы в `schemas.py`.
4. Реализуй сценарии в `service.py`.
5. Добавь `models.py`/`repository.py`, если нужна таблица. Затем — миграция Alembic.
6. Добавь роутер в `router.py` и подключи его в `app/main.py`.
7. Напиши тесты: доменную логику — юнитами, эндпоинты — через httpx.

## Пример подключения роутера

```python
# app/main.py
from app.modules.<имя>.router import router as <имя>_router
app.include_router(<имя>_router, prefix="/api/<имя>", tags=["<имя>"])
```
