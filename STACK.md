# НК-ЛАБ — Технический стек (Этап 1)

Документ описывает выбор технологий для бэкенда, фронтенда и инфраструктуры MVP.
Версии проверены на июль 2026 года.

Про архитектуру, слои и структуру проекта — отдельный документ `ARCHITECTURE.md`.

Принцип выбора один: **берём скучный, проверенный стек.** Скука здесь — достоинство.
На каждую технологию есть готовые ответы, специалисты на рынке и предсказуемое
поведение в проде.

### Пояснения к выбору

**Про async.** FastAPI async по умолчанию. Но не гоняйтесь за ним ради галочки.
Тяжёлый разбор Excel и построение вариаций — это CPU-работа, async её не ускорит.
Async нужен для операций ожидания: запросы к внешнему API НК на этапе 2. Пока
можно спокойно писать синхронные обработчики там, где так проще.

**Про SQLModel.** Соблазн объединить Pydantic и SQLAlchemy в одном классе. Для
НК-ЛАБ не советую. Модель хранения и API-контракт у вас разойдутся: JSONB-атрибуты,
вычисляемые поля, разные представления карточки. Держите два слоя схем раздельно.

## 2. Фронтенд

Фронтенд держим максимально лёгким. Это B2B-кабинет за логином: тут не нужны SEO,
серверный рендеринг и прочее, ради чего берут тяжёлые фреймворки. Поэтому стартовое
ядро — минимальное, а сложность добавляется по лестнице ниже, когда стартап растёт.

### 2.1. Минимальное ядро (старт)

| Компонент | Выбор | Версия | Зачем |
|---|---|---|---|
| Сборка | Vite | 6+ | Мгновенный дев-сервер, простая ментальная модель. |
| Библиотека UI | React | 19.2 | Стандарт рынка, знает вся команда. |
| Язык | TypeScript | 5.x | Типы контрактов синхронно с бэкендом. |
| Компоненты | Ant Design + иконки | 6.x | Таблицы, формы, статусы «из коробки» — закрывает 80% кабинета. |
| Роутинг | React Router | 7.x | Простая навигация в SPA. |
| Запросы к API | axios | актуальная | Тонкий клиент + пара своих хуков. Без лишних абстракций. |

Состояние на старте — собственное состояние React: `useState` и `useContext`.
Никаких внешних стор-библиотек, пока боли нет.

### 2.2. Лестница усложнения (по мере роста стартапа)

Ключевая идея: **ядро выбрано так, что каждый следующий уровень достраивается
поверх, а не вместо.**

| № | Сигнал (боль) | Что добавляем |
|---|---|---|
| 1 | Ручной кэш и повторные запросы стали болью | **TanStack Query** 5.x |
| 2 | Общее клиентское состояние переросло Context | **Zustand** |
| 3 | Формы стали большими и сложными | **React Hook Form** |
| 4 | Код вырос, файлы расползлись | **Модульная структура по фичам** |
| 5 | Бандл потяжелел | **Ленивая загрузка роутов** (`React.lazy`) |
| 6 | Нужна публичная витрина с SEO | **Next.js** отдельным проектом |
| 7 | Дизайн-система стала ценностью | **Storybook + токены темы** |
| 8 | Реальный масштаб, большая команда | **Redux Toolkit / строгие границы модулей** |

### 2.4. Требование среды

Node.js 20+, лучше 22 LTS.

## 3. Инфраструктура

**Где хостим.** Российский облачный провайдер — Yandex Cloud, VK Cloud или Selectel.
Жёсткое требование 152-ФЗ: данные клиентов должны лежать в РФ.

**Контейнеризация.** Docker + Docker Compose. Для этапа 1 достаточно. Kubernetes не
нужен и вреден.

Минимальный `docker-compose` на старте:

```
services:
  api        — FastAPI за Uvicorn
  db         — PostgreSQL
  nginx      — реверс-прокси, TLS, отдача статики фронтенда
```

**Хранилище.** S3-совместимый бакет — под исходные файлы импорта и этикетки.

**Секреты и конфиг.** Переменные окружения + `pydantic-settings`.

**CI.** Простой пайплайн: линт (ruff), тесты (pytest), сборка образа.

## Итог по стеку

Бэкенд намеренно скучный и проверенный: FastAPI, PostgreSQL. Фронтенд — минимальное
ядро на Vite + React + Ant Design. Начинаем с лёгкого — усложняем только под
конкретную боль.
