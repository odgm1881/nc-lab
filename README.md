# НК-ЛАБ — прототип (Этап 1)

Платформа подготовки и валидации карточек товаров для **Национального каталога** и
маркировки одежды (Честный ЗНАК). Клиенты — импортёры одежды и селлеры маркетплейсов.

Главная ценность: **валидация карточек, вариаций, GTIN и РД до заказа кодов.** Мы не
«печатаем этикетки» — мы устраняем ошибки на этапе описания, пока цепочка
`НК → GTIN → РД → коды` ещё не порвалась.

Документы проекта: [`CLAUDE.md`](CLAUDE.md) · [`STACK.md`](STACK.md) ·
[`ARCHITECTURE.md`](ARCHITECTURE.md).

## Что реализовано в прототипе

| Модуль | Что делает |
|---|---|
| **auth** | Регистрация/вход по JWT, роли `client` / `operator`. |
| **import_data** | Импорт номенклатуры из **Excel/CSV/1С**, автоопределение заголовков, нормализация строк, задание импорта со статусом. |
| **variations** | Раскрытие модели в SKU декартовым произведением `цвет × размер × пол × комплектность`. Каждая комбинация — отдельная карточка (правило легпрома). |
| **catalog** | CRUD карточек НК: фиксированные поля колонками, атрибуты категории и РД — в JSONB. Статусы `draft → validating → valid \| error → published`. |
| **validation** | «Ядро правил» — чистые функции `карточка → замечания`, реестр правил, доменная онтология одежды. |
| **gtin** | Формат и контрольная цифра GS1, правило «1 GTIN = 1 карточка». |
| **rd** | Структура и полнота разрешительной документации (тип, номер, дата, срок). |
| **operator** | Консоль оператора: спорные карточки и очередь задач со статусами/приоритетом. |

Фронтенд-кабинет (Vite + React + Ant Design): обзор, импорт с предпросмотром, конструктор
вариаций, каталог с фильтрами, карточка с редактором атрибутов/GTIN/РД и панелью
результата валидации, консоль оператора.

## Быстрый старт (локально, без Docker)

Прототип по умолчанию работает на **SQLite** — Postgres для запуска не нужен.

### 1. Бэкенд

```bash
cd backend
uv sync --extra dev
uv run python -m app.seed        # демо-данные (клиент, оператор, карточки)
uv run uvicorn app.main:app --reload
# API: http://localhost:8000   ·   Swagger: http://localhost:8000/docs
```

Демо-логины после сидинга:

- `client@nk-lab.ru` / `password` — сотрудник клиента (импортёр одежды)
- `operator@nk-lab.ru` / `password` — оператор каталога

### 2. Фронтенд

```bash
cd frontend
npm install
npm run dev
# Кабинет: http://localhost:5173  (проксирует /api на :8000)
```

## Запуск в Docker (весь стек одной командой)

```bash
cd backend
docker compose up -d --build
```

Поднимаются три сервиса: **web** (nginx + фронтенд), **api** (FastAPI), **db**
(PostgreSQL). Миграции Alembic и демо-данные применяются автоматически.

- **Кабинет: http://localhost:8080** ← открывать здесь
- API/Swagger: http://localhost:8000/docs

> Важно: сам сайт живёт на **:8080** (сервис web). На :8000 только API — его корень
> `/` намеренно отдаёт 404, страницы там нет.

Переменные окружения — см. [`.env.example`](.env.example). Для прода задать
`DATABASE_URL` на PostgreSQL и надёжный `JWT_SECRET`.

### Про скорость запуска

- **Первый** `--build` долгий: качаются базовые образы и зависимости. Это разово.
- **Повторный старт без изменений кода** — используйте `docker compose up -d` **без**
  `--build`: контейнеры стартуют за секунды.
- **После изменений кода** — `docker compose up -d --build`: благодаря кэшу pip/npm
  пересобираются только изменённые слои (быстро).
- Остановить/запустить уже собранное: `docker compose stop` / `docker compose start`.

Самый быстрый цикл разработки — вообще без Docker (SQLite, мгновенный старт):
`uv run uvicorn app.main:app --reload` + `npm run dev`.

## Архитектура кратко

Модульный монолит с изоляцией доменной логики там, где она чаще всего меняется
(правила НК и разбор вариаций). Доменный слой (`domain.py`, `rules.py`) **не зависит**
от FastAPI и SQLAlchemy — тестируется без базы и HTTP. Подробнее — в
[`ARCHITECTURE.md`](ARCHITECTURE.md).

```
backend/app/
├── core/            # security, exceptions, storage, типы (JSONB)
└── modules/         # фичи: auth, import_data, catalog, variations,
                     #        validation, gtin, rd, operator
frontend/src/
├── api/  auth/  components/  pages/  types/
```

Границы этапа 1 (осознанно не делаем): микросервисы, брокеры/очереди, Kubernetes,
GraphQL, ML в проде, мультитенантность на уровне схем БД. См. `ARCHITECTURE.md §9`.
